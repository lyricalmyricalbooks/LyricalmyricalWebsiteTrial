## 2024-05-19 - Form Accessibility
**Learning:** Found multiple instances where `<label>` elements were visually styled but not programmatically linked to their respective `<input>` elements using `htmlFor`. This is a common pattern when quickly building forms with Tailwind but it breaks screen reader support and reduces usability (clicking the label doesn't focus the input).
**Action:** When adding forms or custom input groups (e.g., variant selectors), ensure that all `<label>` elements use `htmlFor` pointing to the respective input's `id`. Additionally, custom interactive components must implement proper ARIA roles (like `radiogroup`, `radio`) and states (like `aria-checked`).
