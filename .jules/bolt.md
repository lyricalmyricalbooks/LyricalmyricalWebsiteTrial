## 2024-05-12 - Performance Bottleneck Hunt
**Learning:** In `applyCatalogControls` inside `src/app/features/site/CatalogControls.tsx`, searching re-computes `haystack.toLowerCase()` string over `items.title`, `subtitle`, `authorName`, `categories`, and `genres` inside `.filter` every time any query changes or sort changes. Re-calculating the haystack dynamically for *every* item during filtering whenever sort or stock filter changes (since they are in the same applyCatalogControls function) is O(n). Additionally, filtering is synchronous on the main thread, but a smaller optimization is just avoiding redundant joining and lowercasing. Even better would be an optimization for the `CatalogControls.tsx` query input where the `onChange` is updating the query state and triggering `applyCatalogControls` synchronously on every keystroke, which can cause typing lag on large catalogs. We should use a deferred value or debounce.
**Action:** Use `useDeferredValue` for the query in `MainSite.tsx` and `CollectionPage.tsx` to keep the input responsive, and memoize the search haystack on the book objects if possible, or just debounce the input. Let's look closer at `SearchOverlay.tsx` which also recalculates `results` synchronously on query changes.
